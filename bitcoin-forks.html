Bitcoin Forks: Soft Forks, Hard Forks and Bitcoin Cash

Bitcoin is an open-source protocol. People can propose changes to its software and rules, but how do those changes become part of the network? This is where the idea of a fork becomes important.

1. What is a Bitcoin fork?

A fork happens when the rules used by different parts of a blockchain network become different.

In software development, a fork can also mean creating a separate version of a project's code. In Bitcoin, the word is often used when discussing changes to consensus rules or the creation of a separate cryptocurrency.

A fork does not automatically mean that Bitcoin has failed. It can result from a software upgrade, disagreement about rules, or a decision to create a separate network.

2. What is a soft fork?

A soft fork is a change to consensus rules that makes the accepted rules stricter while remaining compatible with older nodes that follow the previous rules.

Older nodes may still accept blocks produced under the new rules, even if they do not understand every new feature. They may not independently enforce all the newer restrictions.

↓
NEW, MORE RESTRICTIVE RULES

Older nodes can remain compatible, but may not enforce all new rules.

One important example is Segregated Witness, usually called SegWit, which activated on Bitcoin in 2017.

3. What is a hard fork?

A hard fork is a change to consensus rules that is not backward compatible. Nodes using the old rules may reject blocks that follow the new rules.

If some participants continue using the old rules while others use the new rules, the network can split into separate chains.

A hard fork does not always create two lasting networks. The result depends on whether participants continue operating under different rules.

4. Bitcoin and Bitcoin Cash in 2017

In August 2017, a disagreement about Bitcoin's scaling approach resulted in a hard fork and the creation of Bitcoin Cash (BCH).

Participants disagreed about how Bitcoin should handle more transactions. One side supported keeping Bitcoin's existing block size approach alongside other scaling improvements. Another side wanted larger blocks to allow more transactions in each block.

Bitcoin Cash adopted a separate set of consensus rules, including a larger block-size limit. It became a separate cryptocurrency with its own blockchain.

Bitcoin (BTC) and Bitcoin Cash (BCH) share transaction history before the split, but their blockchains developed separately afterward.

5. What do nodes have to do with forks?

Full nodes independently check blocks and transactions against the consensus rules they are configured to follow.

A node running one rule set can reject a block that violates those rules, even if miners have produced it.

This is why upgrading Bitcoin software is important. Node operators decide which software and rules they run. Miners produce blocks, but they cannot force every node to accept a rule change.

6. Who decides which changes Bitcoin adopts?

Bitcoin does not have one central authority that can simply order everyone to accept a change.

Developers can propose and write software changes. Miners can signal support for certain upgrades. Businesses, wallet providers and node operators also make their own decisions about which software to run.

Ultimately, users and economic participants choose which rules they recognise by deciding which software and network they use. Changes that affect consensus require coordination across the network.

7. Why do forks matter?

  • Rules matter: Different rules can produce different networks.
  • Choice matters: Participants can decide which software and rules to follow.
  • Coordination matters: Changes need broad understanding and coordination.
  • Independence matters: Bitcoin has no single organisation with automatic authority over every node.

Understanding forks helps explain how an open-source monetary network can evolve while participants continue to verify its rules.
